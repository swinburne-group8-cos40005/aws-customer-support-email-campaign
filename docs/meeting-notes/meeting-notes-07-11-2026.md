# Meeting Notes -- Sprint 1 Tracking Workflow and Milestone Setup

**Date:** 7 November 2026
**Project:** AWS Customer Support Email Campaign
**Meeting Type:** Team sync -- sprint planning
**Topics:** GitHub issue workflow, milestone #1, first infrastructure decision issue

## 1. Meeting purpose

Evening sync (Google Meet, 9:33--9:57 PM) to agree how Sprint 1 work is
tracked before the build phase starts: one shared workflow for issues
and pull requests, and a milestone that shows sprint progress at any
time.

## 2. Issue workflow agreed

- One issue per endpoint/work item; one branch and one pull request
  per issue.
- Issue status is edited directly on the issue (e.g. from in-progress
  to done) so the milestone stays accurate without separate status
  reports.
- The workflow was walked through live on the call. In-call messages
  (9:47 PM) asked whether issues can be edited with automatic status
  transitions from in-progress to done; the answer was confirmed at
  9:51 PM.

  #6, #7, #8, #9, #10, #11, #20, #21); #12, #13, #14 explicitly
